# Contributing to WPS Sentinel

Thanks for your interest in contributing. This is a lite, vanilla JS project — keep that spirit in mind when proposing changes.

## Ground Rules

- No frameworks (React, Vue, etc.) — keep it vanilla
- No new heavy dependencies without discussion
- Never commit API keys, credentials, or sensitive data
- Keep the codebase readable and minimal

## Workflow

1. Fork the repository
2. Create a feature branch
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. Make your changes with clear, focused commits
   ```bash
   git commit -m "Add: brief description of change"
   ```
4. Push to your fork
   ```bash
   git push origin feature/your-feature-name
   ```
5. Open a Pull Request with a clear description of what you changed and why

## Pull Request Guidelines

- One feature or fix per PR
- Describe the problem your PR solves
- Test in both light and dark mode
- Test on mobile viewport (≤860px)
- Make sure `npm run build` passes before submitting

## Reporting Bugs

Open a GitHub Issue with:
- Steps to reproduce
- Expected vs actual behavior
- Browser and OS

## Code Style

- 2-space indentation
- Single quotes for strings
- Descriptive variable names
- Comment non-obvious logic

## Questions

Open a GitHub Discussion or Issue — happy to help.
